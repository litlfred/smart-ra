For a given health goal, the architecture begins with the goal itself and the sub-goals that compose it. Each sub-goal is associated with the outcomes that indicate progress towards it and with the capabilities the health system needs in order to achieve it. Those capabilities are then connected to the elements that realise them — the services exposed by application components, and the shared data those components hold and exchange. Read from top to bottom, a single view connects a health objective to the specific infrastructure that supports it; read from bottom to top, it shows what each component contributes to the architecture.
