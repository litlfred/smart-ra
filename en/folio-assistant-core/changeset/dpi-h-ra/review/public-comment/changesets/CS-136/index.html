Reframe the Client Registry definition around governed, uncertain identity
requirements
- Describe records as possibly provisional, incomplete or at differing assurance levels, reconciled later - State that financing systems resolve identity via the registry while enrolment/eligibility live elsewhere - Define the 'canonical record' as a governed reference that keeps source provenance, match confidence and correction history - Remove facility-attendance history from the Facility Registry; place it in encounter or LHR data - State that identity and demographic data remain sensitive personal data even though no clinical data is held - Define how consent records identify subjects, representatives and authority - Explain overlap and differences between Client Registry, MPI and EMPI, and how persons' roles (e.g. carer) are represented - Make shared identity patterns with the Workforce Registry explicit while keeping domain differences
