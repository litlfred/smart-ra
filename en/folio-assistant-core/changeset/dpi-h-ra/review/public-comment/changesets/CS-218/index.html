Explain the purpose and reading of the Appendix E mappings
requirements
- Say the tables are one reference decomposition, not the only valid architecture - Open the appendix with who the mapping is for and what decisions it supports (priority setting, capability assessment, investment planning) - Lay out large tables for legibility (orientation, repeated headers, grouping, font size) - State that the mapping is logical and can be realised by centralised, federated, regional or transitional arrangements - Add a legend defining goal, sub-goal, outcome, capability, service, component and application, with one worked example read end to end - Provide tagged tables, text alternatives, sufficient contrast and no reliance on colour alone - Note that recurrence of a component across goals is one criterion among several for shared infrastructure - Indicate which view suits policy/financing readers and which suits technical teams
