SMART Guideline end to end

Process_SgEndToEnd · advisory · 17 step(s)

From a use case to a consuming application: identify the L1 guidelines, ingest them into an L1 knowledge graph, choose the L2 DAKs to build on, create or adapt the L2 assets, choose the L3 IGs to build on, produce the L3 assets, then build the application the requester describes. Adjudication follows every stage as QA, not as a gate (owner, 2026-10-14: “once agent produces L2 it can produce L3”): each stage forks into the next stage and its adjudication, and each adjudication has its own end event, so the instance completes only when all are recorded. The stages run the existing skills and processes (l2-dak-authoring.bpmn for stage 4, dak-l3-ig.bpmn for stage 6); the smart-guideline-end-to-end skill says which, and who adjudicates each.

Lanes — who acts

lane role what it does here
Requester (country team / implementer) user The person who wants the guideline and the application. Describes the use case (stage 0) and the consuming application (stage 7). The agent asks; it never invents either.
Authoring agent authoring-agent Runs every authoring stage with the skill named on each activity. Goes straight on to the next stage after each one: adjudication runs beside it, as QA, not as a gate (owner, 2026-10-14).
Human adjudicators reviewer Clinical SME, l1-extraction-reviewer, programme manager, business analyst, FHIR modeller, terminologist: which one signs each stage is in the smart-guideline-end-to-end skill. Each adjudication calls cat-harness’s generic review, Process_Review, on the staged preview (feature-staging, staging-review) and records a qa-review/v1 Decision (approve, request-changes, reject) with the adjudicator’s role id. Each adjudication ends in its own end event, so the instance is complete only when every adjudication is recorded. A rejection files a bean against the stage and marks every downstream asset derived from the rejected item rejected-upstream; it does not stop the agent.
