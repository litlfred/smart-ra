Treat offline-first and low-connectivity operation as a core design condition
requirements
- Set minimum offline-first requirements (local capture, store-and-forward, sync, deduplication, reconciliation) where connectivity is intermittent - Cover offline-first data capture and synchronisation for community health workers - Translate intermittent connectivity into requirements: caching, queues, retry, deduplication, reconciliation, conflict handling - State that offline resilience needs local availability, store-and-forward and conflict resolution regardless of topology - Apply them consistently to REDDHI, implementation guidance, HMIS, surveillance reporting and workforce credential checks - Define minimum conflict-resolution and reconciliation rules for offline and federated updates - Address identifier assignment and persistence offline without collisions - Do not imply that federation alone provides offline resilience
