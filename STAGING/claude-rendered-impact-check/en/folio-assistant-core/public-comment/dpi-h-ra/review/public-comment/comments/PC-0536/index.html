This comment states the Ministry's substantive recommendation in one place, so that it is not distributed across the individual comments that follow. The guidance should name an open information-model formalism for the persistence of clinical data, and should recommend openEHR archetypes and templates for that role, with ISO 13606 as the ISO-ratified equivalent, in the same way that it recommends HL7 FHIR for services and transactions in section 4.3.3. HL7 FHIR should continue to be recommended for exchange, and is also appropriate for the persistence of demographic, administrative and encounter data. Slovenia applies exactly this division nationally. The reasons are matters of design intent and lifecycle cost, not preference. FHIR is designed for data in motion, as section 3.6.2 line 813 states, and its major versions introduce breaking changes — appropriately, because both endpoints of an exchange can upgrade together. A national record that persists clinical data in that form must migrate its entire data estate on the exchange community's release schedule; data at rest cannot run on a cadence set by the needs of data in motion. A two-level model, in which a small stable reference model is separated from clinical content governed as archetypes and templates, allows clinical definitions to change without migrating stored data — which is the outcome the guidance asks for at page 173 lines 55–59, where domain experts update definitions "without depending on software vendors to make those changes", but for which it names no mechanism. Provenance, versioning and audit are carried structurally for every data element rather than added profile by profile, meeting the LHR core attribute at page 157 lines 119–121. And the guidance's own observation at page 96 lines 335–338, that conformance is hardest to retrofit where underlying data structures are not conformant, applies with most force to the record itself. This is not a position peculiar to Slovenia. Catalonia, already present in Annex D.2, has adopted openEHR archetypes for the clinical information layer of its electronic clinical history platform, and a Delphi consensus commissioned by the Spanish Ministry of Health reached the same conclusion independently. Three European health systems of very different scale have converged on the same division of standards by role. The Ministry is not asking for exclusivity, and does not propose that FHIR be excluded from persistence where a country has chosen it. We are asking that the persistence layer be given a named recommended framework, as the exchange layer already has, and that the recommendation reflect what the guidance already accepts in Annex D.1 and requires in Appendix C.
