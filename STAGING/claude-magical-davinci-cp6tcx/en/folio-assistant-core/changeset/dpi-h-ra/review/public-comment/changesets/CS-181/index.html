title
Define the CDSE boundary, deployment options and knowledge artefacts
requirements
- Present decision support as a logical capability that may run as a shared service, embedded locally or on-device, consuming the same governed artefacts - Require an intended-use statement and authority/provenance metadata (source guideline, jurisdiction, dates, owner) for each artefact - Distinguish computable knowledge management from rule or model execution, and both from interaction standards such as CDS Hooks - Use implementation-neutral wording where 2.1 describes how the CDSE evaluates a record - Require version-pinned dependencies on terminology, data models and value sets, with coordinated release and compatibility testing - State that the CDSE exposes decision services while point-of-care applications own workflow integration - State safe-failure behaviour when a remote service is unavailable: fallback, cached guidance, clear indication, queued work and reconciliation after recovery - Require enough recorded context to reproduce an execution result
